# 012 – USB virtual COM port (CDC)

The board shows up on the PC as a USB serial port. Every message the PC sends comes back as
`Gelen Mesaj : <message>`. The USB device library and the CDC class are generated by CubeMX;
the application code is in `USB_DEVICE/App/usbd_cdc_if.c` and the main loop.

## Wiring

Two cables:

| Connector | Purpose |
|---|---|
| Mini-USB (CN1, ST-LINK) | Power, programming and debugging |
| **Micro-USB (CN5, USB OTG)** | The virtual COM port |

After flashing, Windows lists a new **USB Serial Device (COMx)** in Device Manager → Ports. Open
that port in the terminal (Termite, PuTTY, Tera Term). The baud rate setting does not matter on a
USB CDC port. The ST-LINK's own *STLink Virtual COM Port* is a different port and does not carry
this project's data.

## Configuration

| Setting | Value |
|---|---|
| Peripheral | USB_OTG_FS, device only, VBUS sensing on PA9 |
| Class | CDC (communication device class), full speed, 64-byte packets |
| Clocks | HSE 8 MHz → PLL (M = 4, N = 72, Q = 3) → **48 MHz** for USB; SYSCLK HSI 16 MHz |

## How it works

- `CDC_Receive_FS()` runs inside the USB interrupt when a packet arrives. It copies the packet into
  `usb_receive_msg`, leaving room for the terminating `'\0'`, sets `usb_arrive_msg`, and re-arms
  reception with `USBD_CDC_ReceivePacket()`.
- The main loop sees `usb_arrive_msg`, clears it, formats the answer with `snprintf()` and sends it
  with `CDC_Transmit_FS()`.

## Notes

- `usb_arrive_msg` is shared between the interrupt and the main loop, so it is `volatile`, and its
  `extern` declaration in `main.c` has no initializer. `extern uint8_t x = 0;` is a second
  definition and fails at link time with `multiple definition`.
- `CDC_Transmit_FS()` only starts the transfer; the bytes are copied to the USB FIFO later, in the
  interrupt. The send buffer in `main.c` is `static` so it is still valid when that happens.
- `CDC_Transmit_FS()` returns `USBD_BUSY` while a previous transfer is in progress; this example
  sends at most one answer per received packet, so it does not retry.
